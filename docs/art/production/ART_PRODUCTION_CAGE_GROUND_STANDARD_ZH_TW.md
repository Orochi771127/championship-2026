# 籠子地面標準 v1（2026-10-28）

- **適用範圍：** 牧場 3D 籠子（`assets/production/cage/three-20261021/field_cmXX_01.glb`）的可走地面。
- **用途：** 往後新做的籠子地圖都照這份做。
- **Owner 指示：** 長期方案，且要適合網頁遊戲。

## 為什麼要有這份標準

10-24 的匯出把整個籠子烘成一張 1024 共用貼圖，地面只分到每單位約 9～54 個像素。為了換顏色，母檔又在底板上疊了好幾片薄片。實機因此出現三種問題：

1. **黑邊：** 薄片側壁的 UV 被壓成一條線，讀到未填色的黑色縫隙，形成黑色斷層線。
2. **髒影：** AO 把白線、薄片和草叢都當成遮擋物，留下髒影和黑麻點。
3. **分區糊：** 分區顏色只能做到貼圖解析度。

## 標準

### 1. 地面只有一張底板

- 分區（跑道、草皮、沙地、地墊）畫在**地面圖**裡，不再用疊在底板上的薄片換顏色。
- 舊籠子的薄片若要併入地面圖，寫在 `ABSORB` 或 `LANE_ZONES`。其他薄片保留在共用貼圖，邊緣仍然由幾何決定，所以是銳利的。

### 2. 地面圖（ground map）

- **形式：**
  - 每籠一張俯視彩色圖，涵蓋模型座標 XZ 的矩形 `bounds`，第 0 列是 z0。
  - 以 WebP（q90）放在同一個 GLB 裡，影像名稱 `ground-map`。
- **宣告方式：** 寫在地面材質的 extras：
  `cageGroundMap: { version: 1, texture: <texture index>, bounds: [x0, z0, x1, z1] }`
- **覆蓋遮罩：**
  - 用材質 metallic-roughness 貼圖的**紅色通道**（glTF 的 occlusion；這個材質原本沒用到）。
  - 地面頂面的貼圖像素為 1，其他一律為 0。
  - 只讀到地面薄片的縫隙像素也設為 1，讓壓扁 UV 的小面直接取地面圖。
- **解析度：**
  - 一般為底板貼圖密度的 1.5 倍，至少每單位 32 px。
  - 程序生成的分區（跑道、地墊）可到 64 px。
  - 最長邊不超過 1024。
  - 讀取時沿用場景的 `textureCap`：省電 512，平衡 1024，高畫質 2048。
- **節點限制：** 地面網格及其上層節點必須是單位變換，因為執行時用的是原始 `position`。
- **向後相容：** 沒有宣告的籠子完全照舊。

### 3. 接觸陰影只算真正的遮擋物

- 只有高於底板 10 cm 的三角形才算遮擋物。
- 底板、地面薄片、地面標線、草叢都不算。
- 陰影寫進地面圖，下限 0.55，不會死黑。

### 4. 地面標線與真實高低差

- **標線：** 做成獨立的幾何，不參與 AO。
- **真實高低差（高台、舞台、水池、階梯）：** 必須有側壁、路緣或斜坡，不可是懸空薄片。
  - 37 張盤點結果：只有 cm37 的雲片沒有側壁，它屬於天空裝飾。

### 5. 幾何修改

- **原則：** 能只改貼圖就只改貼圖。必須動幾何時，Draco 重新編碼時要讓保留下來的頂點逐位元相同（逐張找出能還原的量化位數，最後才用無損）。
- **支撐籠：** 用精確頂點重新對應 `physical-ground-tops.r2.json` 的三角形索引。
- **測試夾具：** 同步更新 `tests/fixtures/ranch-v4/*-triangle-remap.json`。

## 執行時

- **模組：** `src/championship/presentation/cageGroundMap.js`。
- **流程：**
  1. 載入 GLB 後讀出地面圖。
  2. 等所有既有的著色器掛鉤（水、岩漿、風）裝完後，串接到它們之後。
  3. 依覆蓋遮罩把地面圖混進 `diffuseColor`，並保留材質色（`diffuse`）。
- **適用畫質：** 所有畫質都會套用。
- **診斷：** `getDiagnostics()` 的 `groundMaps`、`groundMapsHooked`。

## 製作流程（單進程 Blender，封存在 `R:\Projects\Championship2026\cage-ground-20261028\scripts\`）

1. **盤點：** `ground_scan.py`。把母檔物件分成 A 薄片、B 標線、C 高低差，並標出色塊與縫隙。
2. **幾何（需要時）：**
   - `cm02_geometry.py`：刪掉橫穿直線與薄片側壁，支撐小面改指向內場的 UV。
   - `gym_geometry.py`：每個置物櫃配一個獨立色塊，並重新對應 cm34 的支撐資料。
   - 母檔同步另存新版，例如 `CM02_master_r6.blend`。
3. **地面圖：** `ground_map.py`。
4. **打包與安裝：** `ground_pack.py` → `finalize_install.sh`。後者依序執行：安裝、雜湊釘選、公開選擇、合約雜湊、cm34 夾具。
5. **驗證：**
   - `capture37.cjs`：37 張前後對照。
   - `review/diag.cjs`：檢查每張籠子的掛鉤狀態。
   - `ingame/ranch_shot.cjs`：在 8761 跑實機畫面，角色在場。
   - `npm run test:ci`、`build:playtest`、`validate:playtest`。

## 網頁預算（2026-10-28 實測）

- **下載量：** 32 張 GLB 合計 24.5 MB → 22.9 MB。
  - ORM 紅色通道清成 0/1 後壓得更小。
  - cm02 為 1.27 MB → 0.88 MB。
- **GPU：** 每個放置中的籠子多一張 512～1024 的貼圖。省電畫質會壓到 512。
- **繪製呼叫：** 不變，同一個材質多一次貼圖取樣。
