# 全名冊像素外觀更新與自動置換

執行入口：[全名冊造型重新設計與審查進度](settings.html)。最新 Owner 要求全員並行開始，不再以 M201 反覆試作作為其他角色的前置阻塞。第一階段的舊方法審查見 [stage-01-review.json](stage-01-review.json)；這份歷史通過紀錄不代表最新身份方向通過。

## 最新外型方向與全員作業

Owner 以大型二足裝甲爪獸作為改造幅度的例子，明確提出「貓化、可愛大眼化、犬化、龍人化、獸人化」，並授權開工；隨後要求盤點全部角色並全部開始，不要每次只做 M201。

- 保留原本動作體型，逐隻重設頭臉、眼眉、口鼻、材質、毛色／鱗片、裝甲分區與允許的局部輪廓。貓狗不設定固定配額，大眼可與其他身份混合；特殊體型逐隻說明取捨。
- 全部 224 套先建立可追溯的來源單體見證與具體設計 brief；216 隻一般角色分三組各 72 隻並行，8 個蛋另列。不能把 brief 當成新畫稿。
- 每隻在全員圖庫顯示已觀察的體型、選定身份、至少三個具體識別特徵、改動區域、保留動作、可改輪廓與風險。不得僅依名稱分配物種或虛構進化家族。
- 各組同時繪製不同角色的原生像素單體稿。單姿態可以提前展示並繼續補稿，但不能宣稱代表姿態或全動作已通過。舊 16 套依最新方向重審，不讓它們阻塞新角色開始。
- 新身份審查版本為 `creature-identity-v1`。設定必須有 `identityDesign`，实际視覺審查必須明列相同方向版本與 `PASS_IDENTITY_DIRECTION`；加入欄位本身不構成美術核准。
- 圖庫分别計數「來源已看／方向已定」「新身份已繪」「代表姿態通過」「完整動作／預設置換」。歷史像素稿和舊 PASS 留存，但不繼承新身份的通過狀態。

最新全員方向見 [identity-design-queue.json](identity-design-queue.json)，來源見證見 [identity-source-survey/index.json](identity-source-survey/index.json)。來源見證是參照，不是新角色素材。

Owner 已確認以資料夾實際盤點為準：**224 套全部更新，216 隻一般角色＋8 個蛋**。284 是記憶誤差，不建立額外虛構角色。這不是四隻示範結案；四隻為每批的檢查單位，全部 56 批都有 redesignRequired。

正式製作改用原生像素網格、共用普通色盤（最多 15 個可見色＋透明）、完整母版引用及有來源證明的局部共用區域。保留 M201 A、M001 B、M226 B、E000 A；之後由已授權美術總監選擇低風險設計並返修。高清候選保留為歷史參考，不再逐格獨立生成。

一隻完成全部母版、回填 Main/Sub、通過美術／動作／技術包／正常場景檢查並具備既有登記所需證據後，自動切换該隻的正常預設，不必再次等待 Owner 逐隻下替換命令。未通過的角色自動返修並保留前一合格版本；不得用原圖補缺後宣稱完成。公開發行與未執行的實體裝置驗收保持獨立。

製作順序修訂（美術總監依已授權自主決策，回應 Owner 希望先建立全員單體設計的建議）：**代表體型驗證 → 224 套像素外觀設定 → 按角色展開完整動作與自動置換**。先建立每隻的身份依據，再投入大量動作稿；不再要求先畫完 M201 全部 47 母版才開始其餘角色的外觀設定。

前兩批八套 M201、M001、M226、E000、M222、M228、M352、M431 保留為代表體型與歷史方法證據；依新方向重審，同時讓其他角色開始單體製作。M201 母版／色盤／槽位連動實例繼續作工具測試，不再作其他角色開工的前置阻塞。原有選案保留；不適配的細節逐隻返修。八套不代表所有特殊結構都已驗證，其他例外仍逐隻檢查。

第二階段以四套一批建立全員設定，優先完成 224 套的外觀覆蓋。每套交付一份「可製作的像素角色設定」，包含：

- 原生尺寸標準姿態、整數倍率放大稿及手機顯示縮圖。
- 固定普通色盤、眼口像素規則、三至五個識別特徵；必要時列出朝向／遮擋變體。
- 原有姿態範圍與共同原點限制，以及可以改動輪廓的區域。
- 一般角色先用三個有來源依據、差異較大的姿態檢查身份一致性；姿態不足時檢查全部。蛋檢查全部。特殊結構按風險追加，完整製作仍沿用最多十二個高風險姿態的審查。
- 設計版本、已確認規則、尚未確認部位和局部共用關係。只有相同像素與適用上下文均有證據的部位才登記共用。

設定板可以集中比較輪廓、主色與臉部差異，避免全員都長成同一種幼獸。設計以原生像素稿定版；高清概念稿只能作參考。這一階段完成不計為全部動作完成，也不觸發正常預設替換。

第三階段依設定版本逐隻展開全部動作。M201 仍是第一隻完整角色包的驗證對象：47 母版、83 槽位、53 序列，先證明 Main0/4/6/Sub0 整格連動與九槽 16×8 局部連動，再完成全部獨立母版。後續依既有全名冊佇列製作。像素編輯可以共用相同圖像，不能把 OAM 硬體矩形當解剖骨架，也不能以一張站姿自動變造全部姿態。

一致性的製作依據是同一份版本化設定、色盤、母版與明確局部變體。設計若返修，依引用表標記受影響的動作並重新檢查；不同姿態不靠同一段提示詞重新猜角色。自動化負責引用回填、色盤傳播、編譯、檢查及合格整包的預設切換，姿態差異仍須依原始資料編修。

色變只有像素與透明形狀對應證據成立才可派生。M2018→44/46 已有色表證據；黑／白輪廓及其他不同形狀保留獨立變體或明確狀態 mask。

最終輸出維持 RGBA PNG、PixiJS JSON 與既有 production index。原序列、ticks、mode、loop start、每槽共同原點及 gameplay owner 不變；不同角色使用各自的座標約定。正式整隻驗收與研究預覽分開，示範頁不等於正常遊戲整合。

全名冊要求見 [production-queue.json](production-queue.json)，執行政策見 [policy.json](policy.json)。狀態各自記錄：像素設計→全部畫稿→美術→動作→技術包→正常場景→預設已替換。資料齊全不代表畫稿完成；技術測試不代替美術／實機檢查。
