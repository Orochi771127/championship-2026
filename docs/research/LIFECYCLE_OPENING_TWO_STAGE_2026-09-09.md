## 同輸入的 Home 重建對照

新增只讀原作追蹤來自同一個 `food-eaten.dst`，只輸入手寫筆座標與 frame，不改 RAM。流程為第 4 日手動結束、日曆確認、第 5 日 07:00。原 ROM SHA-256 是 `8ad375ba0bd9b652a25f72dead2b47f78da401e188a8f3e1b7a6f2867ee0c5d1`。

`trace-raising-native.py` 現可在指定原指令命中時保存私有 RAM checkpoint；這是讀取功能，不含寫 RAM 命令。`export-raising-home-rebuild.py` 只輸出 profile、座標、RNG、時間及操作證據，原 RAM、ROM、圖片留在私有 archive。

四個檢查點是 Home 建立前、所有角色建立後、兩段過夜後、次晨 writer 完成後。此次對照暴露並修正：

1. Cage 必須保留原 pool 記錄順序 `35, 0, 1, 15`，不能依畫面 slot 排序。
2. `0204FC8C → 0204FE20 → 02116B70` 在新角色加入同籠時，通知既有角色。通知會消耗既有角色的 channel，發生在新角色方向初始化與位置採樣之間。這個 draw 不是 idle 入場。
3. 重建後的環狀串列，從最新成員開始，再到最舊成員及其後順序。角色與食物都必須保留這個遍歷順序。
4. 原作先重建角色，再執行兩段過夜，最後執行 morning writer。原 day-end save 保留 root `+BC` 的待處理時間；app 使用同一份 v5 save 的 `nativeHome.pendingOvernightMinutes` 承接。

原故事由 ARM9 `0208E964` 依序更新四個 `02090474..020906E4` 控制器；圖片／文字元件數為 `4,2,2,1`，等待參數位於 `020A953C`，數值 `500,750,900,300`。元件展開完成後進入閱讀等待，只有這時的 touch-release 能提早捲動。過早點按不跳過內容。四張繁中內容是大會週期、參賽資格、迎向冠軍，以及收到郵件。

[原 CPU 紀錄](OPENING_STORY_CPU_CHECK_2026-09-09.json) 比較五條路徑共 **7,562 個更新 frame**，包含全程自動、每 frame 點按、過早點按、閱讀時點按及混合輸入。所有 frame 的狀態、等待、展開比例、元件進度及捲動值均以 trajectory SHA-256 比較，另保留轉換點數值。圖形、聲音與硬體時間不由這個 CPU harness 驗收。

`nativeOpeningStory.js` 是純數值控制；`openingStoryPresentation.js` 將有限的 frame 軌跡交給 DOM Web Animations，不加入另一個 Pixi 或遊戲 ticker。背景、圖形及繁中文字均為獨立編寫，沒有載入 ROM 圖片；目前只完成原順序和操作，**不能稱為原故事插畫的完整視覺還原**。瀏覽器已驗證自動／點按到信封，再到登錄信與姓名輸入；重載未完成命名時仍保留舊存檔，Continue 不重播故事。
