## 證據範圍

- 直接操作網頁播放器、選取時間點並檢視保存影格；重點加密在約 04:28–04:32、05:01–05:04。其餘時間採樣，未宣稱完整逐幀觀看或涵蓋所有遊戲分支。
- 本片是剪輯攻略：包含放大的遊戲單螢幕、原作雙螢幕、兩組畫面的左右比較、作者製作的條件表、角色插圖與字幕。這些編輯排版不能當作遊戲本身的 UI 位置。
- 大部分遊戲文字為英文；約 04:25 又出現日文實機畫面。不能當作同一版本、同一連續存檔的無剪接輸入紀錄。
- `VIDEO_OBSERVED` 為直接可見；`INFERRED_FROM_SEQUENCE` 為前後畫面的行為解釋；`EXISTING_ROM_RESEARCH` 是本次讀取的既有研究，沒有冒充重新執行 ROM 追蹤；未知事項繼續保留。
- 影格索引保存實際播放器時間、目標時間、檔案雜湊與限制。本文時間約取播放器顯示值；秒級擷取與顯示可能有約一秒差異。登入彈窗遮擋的樣本不採為遊戲證據。

## 2. Hunt 的 UI 位置與輸入層級

以片中放大的**單一遊戲觸控螢幕**為基準，世界占上方約 88–90%，底部工具列約占 10–12%。第一格手掌與第二格繩索在所見 Hunt 片段可明確區分；這不是整支影片的相對位置，也不能直接套用到 Training 的同一格。

套繩線在世界中圍繞目標，拉繩線連接目標與端點；Pull!、手掌提示、狀態條都跟隨目標附近呈現。它們屬於世界中的互動回饋，工具列則是固定在螢幕底部的模式選擇。指標、Bilibili 播放控制和作者字幕均不屬於原作 HUD。

玩家操作可拆成以下層級；這是分析分類，不是新增遊戲功能：

| 層級 | 玩家決定 | 本次證據 |
|---|---|---|
| 模式／行程 | 何時狩獵、參賽、繼續養成 | 前片功能選單；本片行事曆與賽事條件 |
| 出發前 | 選獵場、查看費用、配置裝備 | 前片球形地圖與 Settings；本片 Analyzer 商品 |
| 野外工具 | 瀏覽場地、選繩或手掌 | 本片底部高亮切換；既有鏡頭輸入研究 |
| 當前目標／手勢 | 圈繩、拉繩、收取 | 本片兩組捕捉序列 |
| 結果管理 | 命名、決定去留、處理容量 | 前片捕捉結果頁 |

既有 [Hunt 輸入 ROM 追蹤](../HUNT_FIELD_INPUT_ROM_TRACE_2026-08-29.md)把空地拖曳記為鏡頭平移，並區分捕捉、對象與鏡頭的輸入優先序。據此，設計／稽核時應檢查同一手勢是否被當前捕捉操作消耗，避免拉繩與移動畫面同時被觸發。這是交叉核對的工程含義，並非本次已測試目前實作。

## 3. 「獵場 3D 球」的判定

**可以支持：原作 Gate Select 是使用 3D 世界地圖的地點選擇介面，玩家看到球形世界與地點標記。**

| 證據 | 支持的範圍 |
|---|---|
| [前片約 00:45](https://www.bilibili.com/video/BV13u411B7BK/?t=45)、[約 12:41](https://www.bilibili.com/video/BV13u411B7BK/?t=761) | 下螢幕中央是球形地圖與選點標記；下緣是 Settings／Return；上螢幕顯示地區名稱、預覽、說明、Entrance Fee、Funds |
| [既有 Gate Select 3D 契約](../../contracts/championship/VS2_GATE_SELECT_3D_RUNTIME_CONTRACT.v1.json) | 記錄 OVL12 的 NSBMD 載入呼叫 `0x0210C6FC`，唯一呼叫者傳入 `gate_select / 3D_worldMap_model`。這是程式交叉參照，比僅看到含 3D 的檔名更強 |
| 同一契約的模型識別 | `gate_select/3D_worldMap_model.nsbmd`：164912 bytes，BMD0／MDL0／TEX0；SHA-256 `4852ce8731b9b221864d219870bcf7f5f0332645d429893c107b4478e8fef539` |

必須精確保留的界線：

- 球形選擇畫面的直接影格出自**第一支**影片。本次第二支取樣主要補強繩索操作；未在採用影格中取得另一組球形地圖證據，也不據此宣稱第二支完全沒有。
- 契約對世界地圖的結論是 ROM_VERIFIED，但對 `earth.nsbmd` 的精確執行期綁定仍為部分確認。本次沒有追加二進位驗證。
- 選獵場的 3D 世界地圖與進入後的局部捕捉場是不同呈現層級。上述證據不能延伸成所有野外地形、角色或戰場都必須是 3D。
- 旋轉手勢、轉向速度、慣性、吸附、縮放、點位命中範圍與解鎖規則，仍需更完整操作或程式證據。

因此第一份報告「單靠畫面不能證明內部 3D」仍是方法上的限制；**合併既有 ROM 證據後，世界地圖使用 3D 不必再列為完全未知。**

| 非對稱隊伍，約 04:02 | Large Fighter 戰鬥總覽，左方三隻、右方一隻 | 戰鬥畫面要能表達雙方不同人數；不能由前片 Free Battle 的兩個選項推成所有賽事只准 1 對 1／3 對 3 |

整體玩法因此能更清楚地串起：看日程與限制 → 準備合適種類及屬性的隊伍 → 狩獵與養成 → 參賽取得進展 → 牌照與養成上限提升。這是各功能的關聯分析，沒有將作者推薦的培育路線、成長數值或「最快攻略」當作唯一正確玩法。
