# 原作影片畫面、UI 與玩法語意分析

來源：[数码宝贝---冠军｜BV13u411B7BK](https://www.bilibili.com/video/BV13u411B7BK/)，作者「超丸Beletia-Tisha」，13:17。分析日期：2026-09-03。

後續補充：[前期攻略的套繩／拉繩／手掌收取與 3D 地圖交叉核對](../video-BV1RQ4y1B7up/ANALYSIS_ZH_TW.md)。第二支影片補上捕捉中間狀態及非對稱賽事；既有 ROM 研究支持 Gate Select 使用 3D 世界地圖。以下各觀察仍以本片為來源，不混入其他影片的時間點。

這份分析直接檢視影片畫面，並與既有研究交叉核對。核心結論是：**玩家扮演多隻數碼獸的管理者，以場景內的照料、環境配置、狩獵手勢與戰前決策，驅動養成和自動戰鬥。** 原作將「目前狀態／選中對象」與「世界操作／局部選單」分配到不同區域；理解這個分工，比複製雙螢幕外形重要。

## 1. 範圍與證據邊界

- 已以時間軸抽樣覆蓋開頭到尾端，並加密檢視捕捉、子選單、編輯、編隊、日切換等段落；不是逐幀無缺口的輸入追蹤。完整觀察索引見同目錄 JSON／CSV，選定影格見本機圖錄。
- 影片從既有存檔的 Spring Day 5 開始，進展到 Summer Day 1。它涵蓋多種重要流程，但**不能視為全部遊戲內容、完整通關或所有分支的示範**。
- 實拍為英文版《Digimon World Championship》；本機 YDIJ 研究為日文版。功能可交叉參考，但英文標籤不能直接證明日文 ROM 的字串索引、處理函式或版本完全一致。
- 畫面反覆出現 HP／TP 9999/9999、Funds 9999999；影片作者在留言中也提及作弊碼。適合研究介面、可見流程與空間關係；不拿它推算一般養成速度、正常勝率、獎勵平衡或時間倍率。
- `VIDEO_OBSERVED` = 本次直接看到；`ANALYSIS_OR_CROSSCHECK` = 對觀察的解釋或既有資料支持；`UNKNOWN_REQUIRES_TRACE` = 未能證明。看到 UI 不等於已驗證內部規則。
- 時間連結使用取樣目標值；播放穩定後可能前進約 1–數秒，以保存影格內的播放器時間為準。未採用的載入／陳舊影格不列入觀察索引。

## 2. UI 在哪裡：以每個原作螢幕分別描述

下面百分比為視覺估讀，起點是**各自螢幕的左上角**，不是整支影片，也不是未來手機版座標。原始畫面的上下兩區各約 4:3；播放器黑邊、Bilibili 按鈕及錄影浮標不屬於遊戲。

| 畫面／区域 | 位置與占比概略 | 顯示什麼 | 玩家如何理解 |
|---|---|---|---|
| 共用狀態列 | 上螢幕最上方，約前 12% 高度 | 左：季節；偏左：Day；中：Training/Hunt/Battle/Shop；右：HH:MM | 我在什麼模式、哪一天、幾點 |
| Training 對象資料 | 上螢幕中上部 | 中央角色像；右側 HP、TP、AP、Capacity；其下物種／屬性縮寫與暱稱 | 目前正在看哪個個體，以及它的狀態 |
| Training 場地概覽 | 上螢幕約 60–76% 高度 | 左側縮小的場地形狀及紅色框；右側 Change Status 提示 | 提供目前場地／檢視的定位線索；紅框精確綁定仍須追蹤 |
| Training 訊息區 | 上螢幕最下約 22–24% | 剩餘物品、能力變動、上限、進化結果 | 為剛才的行為和自動事件提供文字回饋 |
| Training 世界 | 下螢幕大部分，約前 88–90% | 相鄰多個場地、角色、食物、氣泡、浮字 | 實際選取、放置、搬動與照料發生的位置 |
| 底部工具列 | Training/Hunt 下螢幕最底約 10–12% | 8 個交錯排列圖示，高亮表示目前工具／展開入口 | 切換接下來點擊或拖曳的意思 |
| 彈出子選單 | 下螢幕中下部、工具列之上 | 兩欄交错按鈕，場景仍可見 | 暫時提供下一步功能，不永久遮住生活場景 |
| Hunt 情報區 | 上螢幕左、中、右分區 | 左側雷達樣方框；中間目標像；右側 Gen/Species/HP/Nature/Capacity 等 | 同一個目標的資訊可能仍是 ??? |
| Hunt 槽與倒數 | 上螢幕下方 | 四個槽；左下 Time 倒數 | 不要與全域日曆時間混成同一個計時器 |
| 地區選擇 | 上方說明、下方球形地圖 | 名稱、圖、介紹、入口費、Funds；地點標記與 Settings/Return | 先選去哪裡，再決定配置 |
| Cage Edit | 上方詳情、下方綠色編輯板 | 模組名稱、效果、Occupancy Limit；六角格、各形狀模組；底部 ID/Size/Return | 用整體規劃視角配置生活場景 |
| Shop | 上方商品資訊、下方商品卡與分類 | 圖、名稱、效果、單價、持有量、Funds；New／已持有；購買彈窗 | 檢視 → 選數量 → 確認交易 |
| 戰前配置 | 上方指示或個體詳情、下方隊伍／名單 | 三個成員欄、HP/TP、策略標籤；場地預覽、Battle/Return | 先做組隊和策略決策，再提交出戰 |
| 戰鬥中 | 上螢幕總覽、下螢幕現場 | 上方賽名、雙方隊名、倒數、隊伍狀態；下方移動、攻击、效果、播報 | 上方讀全局，下方看事件；下方此時不是常駐操作面板 |
| 確認框 | 下螢幕中央 | Yes/No 或 OK/Cancel | 覆蓋在原流程之上，處理退出、購買、結束一天等提交 |

**不能把雙螢幕一概寫成「上面只看世界，下面只放按鈕」。** Training／Hunt 的世界在下方；戰鬥時下方也是主要演出區；商店與編輯則是「上方詳情、下方選擇」。角色會隨模式轉換。

由左至右把工具列暫記為第 1–8 格，這只是影片位置描述，不是 ROM 處理器編號。

| 入口 | 直接看見的按鈕 | 證據 |
|---|---|---|
| 第 7 格，倒數第二格 | Tamer、Schedule、Cage Edit、Digimon、End Day | [約 01:57](https://www.bilibili.com/video/BV13u411B7BK/?t=117)、約 07:09 |
| 第 8 格，最右格 | Help、Database、Battle、Save & Quit、Hunt、Shop | [約 01:30](https://www.bilibili.com/video/BV13u411B7BK/?t=90)、約 06:43、13:12 |

第 7 格偏向玩家／飼育管理，第 8 格偏向模式切換與系統功能。這是對分類的分析；按鈕本身及相鄰不同格子的高亮是直接觀察。

其他已能局部對應的工具：最左手形在選取／搬動／瀏覽時高亮；第二格在放食物及 Hunt 繩索操作時呈現不同圖示；約 11:30 的 Protein 操作又使用別的工具。**相同位置在不同模式不能當成永遠相同命令**，未操作到的格子不以圖形猜名。

`Digimon` 和 `Database` 分別在兩組選單內，不能合併成同一頁。本片證明兩個入口存在，沒有完整展示 Database 或 Tamer 內頁。

## 4. 遊戲功能與實際玩法

### 4.1 飼育是持續活動的場景

角色同時在多個相鄰環境活動；食物放進場景後可見實體肉塊，文字區顯示庫存減少。角色有食物氣泡、局部狀態條、移動／訓練動作；畫面會出現 HP UP、TP DOWN、HP at limit 等回饋。

因此玩家處理的不是只有一個「餵食」表單，而是「選工具 → 在某位置或對象上操作 → 看角色反應與訊息」。鏡頭瀏覽、選中角色、搬移角色、投放物品必須分成不同意圖。只有同一段錄影的前後變化，不能自動證明每個數值變動都由最後一次點擊造成。

約 [08:36](https://www.bilibili.com/video/BV13u411B7BK/?t=516) 可見 Punikia 進化成 Coronamon 的訊息與外觀變化。這證明進化屬於養成循環的事件，沒有證明具體進化條件或玩家能自由點選進化分支。

### 4.2 Cage 既是空間模組，也是訓練環境

約 [02:00–02:10](https://www.bilibili.com/video/BV13u411B7BK/?t=120) 及 [10:30](https://www.bilibili.com/video/BV13u411B7BK/?t=630) 可看到編輯板與形狀不同的場地模組；回到 Training 後，以較大、連續的生活场景呈現。

- Playground 顯示 HP Up、Occupancy Limit 6。
- Empty Lot 顯示 Defense Up、Occupancy Limit 2。
- 模組輪廓並非都一樣，有的視覺上跨相鄰六角格。
- ID、Size、Return 是已見按鈕；影片取樣沒有證明 ID／Size 切換後的全部顯示規則。

應分開理解「模組種類」「視覺形狀／佔地」「可容納角色數」「訓練效果」「在場景的位置」。例如容納 6 隻不代表占 6 格。反過來，看到一個模組的資料記錄，也不能推論它的可見佔地只有一格。

### 4.3 Hunt 是空間搜尋與捕捉

本次可見流程：**選地區 → 進入野外 → 拖曳瀏覽 → 使用繩索描繪軌跡 → Pull! 階段 → 退出確認 → 捕捉後管理。**

補充影片另清楚展示 Pull! 後的「倒下／紅手提示 → 手掌工具高亮／收取特效」。上列為本片採樣摘要，不能省略中間步驟而推成完整捕捉狀態機；詳見後續補充報告。

約 [01:01–01:04](https://www.bilibili.com/video/BV13u411B7BK/?t=61) 看得到分段弧線、野生角色上方的 Pull! 與綠條、拉扯連線。這比單張靜態 UI 多提供一層證據：工具真正作用於場上位置及目標。仍不能從短片推定圈線閉合容差、拉力、扣血／耐久公式或多目標捕捉上限。

捕捉後的 Name、Rndm Name、Release、容量與 Return，表示「場上抓到」與「結果名單、去留和容量管理」是不同階段。紅色 066G/64G 是超額狀態的可見回饋；是否允許返回、強制放生或存檔如何寫入，不能只靠這張圖決定。

尾段還展示了設定和繩索庫存清單。Hard Rope 的耐久說明和 Normal Wire 的「鋪在地面阻擋」說明證明兩類工具語意不同。第一段的 ??? 情報及後續 Analyzer／Radar／Memory 商品支持資訊是分層取得的；精確的插件判定仍以 ROM 追蹤為準。

### 4.4 戰鬥重點在出戰前

可見層級為：**戰鬥模式 → 對戰形式／賽事 → 對手 → 己方隊伍 → 成員與策略 → 場地與雙方總覽 → Battle → 自動戰鬥 → 勝利／結果 → 回飼育。** 不同模式可能略過其中一些步驟。

Free Battle 直接提供 [1VS1／3VS3](https://www.bilibili.com/video/BV13u411B7BK/?t=270)；後面 Challenge Gears 也实际演示 1 對 1。隊伍編輯畫面有三個欄位和 Normal Attack 標籤，上方說明可以修改戰鬥策略；本片未展開所有策略選項。

第二支影片補上 Silver Freeze 的 1 對 3 原作文字，以及 Large Fighter 的三隻對一隻戰鬥總覽。因此此處 Free Battle 的兩個選項不代表全遊戲只支援對稱人數。

戰鬥中可見獨立移動、接近、命中／技能演出、青／紅陣營腳底標記、隊伍狀態和播報。取樣片段沒有逐回合選招介面；這與既有自動戰鬥研究一致。不能擴張成「遊戲任何解鎖條件下都絕無干預機制」。

上方倒數 120→099→087 與日曆時鐘並存。它們不是同一種時間；影片錄影／作弊狀態也不適合測量原始 tick 速率。

### 4.5 商店是循序交易

本片首頁直接看到的是 Training Goods、Hunt Item、Cage 三個入口。進入 Hunt Item 後又看到裝備／情報相關子分類。這要與資料庫內部可能採用的分類數分開。

商品卡的 New、綠色選中、You already have it、持有量和價格各有不同語意。Food 的購買窗把單價×數量、Total、Funds、OK／Cancel 並列，先提供可預覽的結果，再由玩家確認。商品說明中 Power 10、Length 24、Durability 32 是「畫面展示值」，不等於已经驗證的計算公式。

### 4.6 日曆、事件與退出

約 [07:09–07:30](https://www.bilibili.com/video/BV13u411B7BK/?t=429) 可見管理選單、白天 13:00 的 End Day 確認、Saving、翌日繼續照料。約 11:00 仍為 Spring Day 8，11:30 已為 Summer Day 1。

這支持兩種時間推进：場景中持續流逝，以及玩家主动結束一天。翌日還可能出現信紙式資訊通知。影片沒有涵蓋全年所有季節、四年冠軍賽資格或完整保存／讀取鏈。

**End Day、退出 Hunt、Save & Quit 是三個不同命令。** 都出現確認框並不表示它們可以共用一個結束行為。

## 5. 玩家操作層級

| 層級 | 玩家正在決定什麼 | 片中例子 | 應保留的回饋 |
|---|---|---|---|
| L0 長期養成與日程 | 今天培養誰、何時參賽、要補哪些能力 | 日期、進化、賽事 Day 7、場地效果 | 日曆、資格、能力與事件 |
| L1 主要模式 | 要飼育、狩獵、戰鬥或購物 | 功能選單六項 | 明確模式名稱與返回路径 |
| L2 流程準備 | 要去哪裡、挑哪場賽、哪件商品 | 地圖、賽事／對手清單、商店分類 | 價格、條件、摘要、預覽 |
| L3 工具／對象／配置 | 正在用什麼，對誰使用 | 選食物、繩索、角色、編隊欄、場地模組 | 工具高亮、對象資料、選中卡片 |
| L4 場內直接操作 | 點、拖、放、畫、拉 | 放食物、搬角色、拖視野、圈選與拉繩、模組搬動 | 軌跡、角色反應、氣泡、浮字、選區 |
| L5 提交與確認 | 是否正式消耗、出戰、退出或跳日 | OK、Battle、End Day Yes、Hunt Yes | 確認框、金額預覽、狀態轉場 |
| L6 執行結果與再決策 | 結果如何，接下來做什麼 | 勝利、捕捉名單、容量、進化、Saving | 專用結果畫面、日志、狀態更新 |

這是分析用的操作分類，不是宣稱原作程式具有同名狀態。L3／L4 常反覆互動，L5 是跨層的提交節點，不必把它們硬實作成單一線性路由。

## 7. 整體畫面與美術層次

原作介面以藍色六角／數位底紋、金色立體框、綠色資料面、亮綠選中、紅色警示／對立資訊組成。標題與勝利有大字、圖形或切場，日常操作保持緊湊資訊密度。

Training 是傾斜俯視的連續設施群：不同地板材質、跑道、管材、醫療空間、樹林、火山，同時容納角色。Hunt 使用較自然的草地、路徑、岩壁等大場景；Battle 則使用更便於辨認陣營、距離與動作的競技場，並加上腳底圈、播報和特效。

可辨識的畫面層次為：環境地面／設施 → 角色／道具 → 狀態與戰鬥效果 → 模式 HUD／工具 → 暫時選單 → 確認與結果。這是視覺遮擋和資訊優先順序的分析，不是從影片直接得出的渲染引擎層級。

球形世界圖、旋轉模式立方體有立體呈現；**單憑畫面仍不能判定即時 3D、預渲染或混合方式**。角色精靈與場景風格也不足以證明底層 API，渲染來源需要 ROM 資源和呼叫鏈佐證。

若轉成單螢幕手機版，應保留「簡潔的季節／日／模式／時間」「大面積可操作世界」「隨選中對象變化的資料」「隨模式切換的工具」「按需展開的管理與功能選單」「獨立確認／結果」。這些是從影片提取的設計約束；新的具體版面仍屬現代化設計，不是原作像素座標。
