# 2026-10-19 bounded public ranch playtest

Owner-approved adaptation: up to 100 total hex cells, initially 20 open; purchases open ten-cell rows for 1,000 test diamonds each. The resident cap remains 16. Cage templates can be bought repeatedly at their existing catalog prices, held in stock and placed as independent instances. Withdrawal returns one copy to stock. Moving a copy retains its identity; withdrawing an occupied copy returns its residents safely to the waiting room.

New public saves receive 8,000,000 Bits and 20,000 test diamonds. Existing saves retain their balances, prior purchases and the first fifty stable cell IDs. There is no catch-up wallet grant, real payment, save-key change or site-data reset. The new representation writes save schema 7; readers for prior schemas remain available. Older game builds cannot read schema 7, so use the current published build when continuing it.

This slice preserves the original cage templates, ground rules and all 366 approved asset entries. No Claude map candidates, new character artwork, source packs or Blender masters enter the public payload. It retains the existing app, router, SavePort, PIXI application and ticker. The bounded grid is not an infinite-world or chunk-streaming implementation.

## Verification scope

Unit/contract tests, a fresh normal browser flow and controlled performance are recorded separately. Browser layout at 390×844 is a desktop viewport check. Every benchmark still has a 100-cell world extent; the varying counts describe unlocked land and actual placed modules.

Detailed local JSON, screenshots and traces are in `.tmp/browser-qa/cage100/`; fixture saves remain there and never replace a user's save. Performance uses fresh isolated Chromium contexts and records the real WebGL renderer. RAF intervals measure cadence; RAF callback CPU does not measure GPU work. Pointerup-to-second-RAF measures a paint opportunity proxy, excluding physical touch latency. Save/quit UI time includes toolbar interactions; synchronous localStorage write time is reported separately. GPU memory and phone hardware are not inferred from JavaScript heap.

## Physical phone follow-up

1. Open the public site in the phone's normal browser and refresh it. Preserve website data; do not clear storage. Existing players should use Continue and verify their original wallet and residents remain.
2. To inspect the larger starting wallet, use a genuinely new save only on a browser/device without an existing save. Confirm 8,000,000 Bits,20,000 diamonds and 20 open cells after normal onboarding. Do not overwrite a valued existing save to perform this check.
3. Buy the eight remaining land rows. Confirm 100 open cells and 12,000 diamonds remaining. Buy the same cage template three times; check the original unit price, exact wallet debit and stock count.
4. Place three copies, confirm, move one and withdraw another. Save and quit, close/reopen the tab and Continue. Check stock, distinct placements, wallet and partner ownership. Feed/carry a partner in each occupied copy and verify ground/shadow/occlusion visually.
5. Record phone model/OS/browser, viewport/DPR, open cells, placed modules, active animated modules and partner count. Observe sustained panning, repeated placement and orientation changes. Report heat, stalls, missing art, rejected saves and reload behavior. Desktop timings below do not establish this acceptance.
