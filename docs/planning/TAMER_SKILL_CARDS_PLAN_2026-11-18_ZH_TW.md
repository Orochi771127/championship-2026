# 馴獸師技能卡企劃（草案）

- 狀態：**草案，等 Owner 定案**（決定事項 `D5_TAMER_SKILL_CARDS`）。還沒有任何實作。
- 來源：Owner 2026-11-18 口述：「馴獸師可以有 20 個技能，自動對戰的時候會從 20 個技能中隨機選三個技能卡來施放…如果要美術圖的話可以跟 Codex 要…也可以加入到天賦技能樹」。
- 2026-11-18 查過產品程式與文件、協調文件、Claude 的記憶與對話紀錄，都沒有更早的書面提案，所以本文是第一份紀錄。
- 分類：`OWNER_APPROVED_ADAPTATION`（定案後）。不是原作行為。

## 1. 一句話

自動對戰時，馴獸師手上有 3 張從自己卡池抽出的技能卡，可以在場邊幫拍檔一把。卡池隨天賦樹長大。

## 2. 規則

| 項目 | 建議 |
|---|---|
| 卡池 | 20 張。開局 4 張基本卡；其餘 16 張由天賦樹解鎖 |
| 解鎖 | 四條線各 4 張。該線投入 3、9、15、22 點時各送一張，不另外花點 |
| 抽卡 | 每場對戰開始時，從已解鎖的卡隨機抽 3 張，不重複。抽選用產品亂數，不讀原作戰鬥亂數 |
| 施放 | 每張一場只能用一次。開戰 10 秒後可用第 1 張，之後每 15 秒多一張可用 |
| 誰施放 | **待 Owner 決定**（見第 5 節） |
| 適用 | 自由對戰、練習對戰、征途爬塔、故事對戰 |
| 頭銜賽、錦標賽 | 依階級限制張數：階級 0–2 帶 1 張，3–5 帶 2 張，6 以上帶 3 張。比照指揮官線的上限精神 |
| 不適用 | 密碼對戰、通訊對戰、線上對戰（對手之間要公平）；教學 |
| 存檔 | 只存「已解鎖的卡」可由天賦推算，所以不必存；只需要存自動施放開關 |

卡片只改戰鬥副本和產品層結算，不改拍檔的原作個體欄位，也不改扭蛋機率。

## 4. 實作落點（定案後）

- 規則：新檔 `contracts/productTamerSkillCards.js`（卡表、解鎖、抽卡、每場張數上限）。純函式。
- 戰鬥：沿用現有兩個產品層入口，不另建戰鬥核心。
  - 傷害、爆擊、開場 TP：`battle/battleTaxonomyAdaptation.js` 已有本隊加成的位置（T3 的 `commander`）。
  - 場上即時效果（回復、暈眩）：`app/battleRuntime.js` 已有 `requestBurst(slot)` 這種對戰中玩家操作，以及場地效果寫入戰鬥狀態的做法。
- 介面：對戰 HUD 加一排三張卡；遵守 `juicy-monster-ui` 的 HUD 規則和 44 px 觸控大小。五語文字。
- 結算：獎勵卡併進現有的對戰結算（和賞金信標、賞金天賦同一筆存檔）。
- 數據競技場：它有自己的模擬，第一批不接，另列一批。

## 5. 等 Owner 決定

1. **誰施放**
   - A（建議）：玩家點卡施放，設定裡另有「自動施放」開關。自動對戰時玩家有事可做，不想操作的人也能全自動。
   - B：全部自動施放，玩家只看。
2. 卡名、效果和數值是否照第 3 節。

## 6. 美術需求（給 Codex）

- 20 張卡圖，每張一個主題圖示，不畫角色動作。和現有道具圖示同一套 HD 像素風格。
- 建議規格：512 × 512 透明底 PNG，另交 128 × 128 縮圖；檔名用卡片 id。
- 四條線各一個底色，基本卡用中性色，讓玩家一眼分得出線別。
- 圖到之前，介面先用程式畫的暫代圖示，並標明待整合；不把暫代圖當成完成。

需求會寫進 Claude 的同步紀錄（`docs/coordination/CLAUDE_SYNC_DELTA.json`）交給 Codex，不改 Codex 的狀態檔。
