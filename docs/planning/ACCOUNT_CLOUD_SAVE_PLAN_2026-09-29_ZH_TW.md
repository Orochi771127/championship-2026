# 帳號與雲端存檔規劃（2026-09-29）

> 狀態：**規劃文件，不是實作授權。** 本輪只完成本機自動保存、真實保存狀態與開發用設計預覽；遊戲內沒有登入、帳號、雲端上傳或任何「已同步」顯示。後端服務、帳號供應商、付費方案、存檔格式遷移與第二個儲存鍵都需要 Owner 另行決定（見 2026-09-28 Owner Direction：accounts or cloud services, save-format migration, paid services need the Owner's decision）。

換句話說：**存檔只在這台裝置的這個瀏覽器**。清除網站資料、換裝置或換瀏覽器就拿不回來；點開狀態列的保存標示，遊戲會直接這樣告訴玩家。

## 2. 目標與非目標

**目標**

1. 換手機、換瀏覽器或清除資料後，進度仍可取回。
2. 同一個帳號在多台裝置接續遊玩，不會悄悄覆蓋任何一邊的進度。
3. 玩家在任何時刻都看得懂「現在存在哪裡、安不安全」，而且畫面說的永遠是真的。

**非目標（這個規劃不處理）**：即時多人、排行榜、線上交易或購買、社群功能、兩份存檔的自動合併、反作弊保證。

## 3. 設計原則

1. **本機優先**：遊玩永遠讀寫本機存檔；雲端是本機存檔的複本，需要明確的上傳、下載或選擇才改變。離線可以照常玩。
2. **沒有假狀態**：「已同步」只在伺服器回覆了相同修訂號與內容雜湊後出現；上傳中、離線、失敗、需要選擇各有自己的字與顏色，**永遠不和「已存到本機」混用**（設計預覽第 5 畫面）。
3. **不自動合併**：本機與雲端不同時，並列真實數字讓玩家選；沒被選的那份先保留為備份。
4. **存檔格式不變**：雲端只在外面包一層信封（見第 5 節），遊戲本身的 `schemaVersion 5` 內容原封不動，讀取仍走現有的 `deserializeChampionshipModernSave` 驗證。
5. **沿用現有權威**：同一個 app、畫面堆疊、保存埠與保存入口；雲端上傳掛在現有保存成功之後，不另建第二套存檔或第二個世界狀態。
6. **同樣的安全時機**：雲端上傳只在本機保存成功之後、且沿用 `safeSaveRoute` 的畫面守門，對戰與狩獵交易中不會上傳。

## 4. 玩家流程（對應設計預覽九個畫面）

| # | 畫面 | 何時出現 | 規則 |
|---|---|---|---|
| 1 | 標題畫面帳號入口 | 每次開啟遊戲 | 未登入明示「存檔只在這台裝置」。服務接通前按鈕停用並標「即將推出」，不做可按但沒作用的入口。 |
| 2 | 登入方式 | 按下登入 | 只建立身分，不上傳任何東西；完成後一定走到 3 或 4。 |
| 3 | 首次登入：匯入本機存檔 | 帳號沒有雲端存檔、本機有存檔 | 顯示本機存檔的真實摘要（馴獸師、遊戲日、位元幣、夥伴數、上次保存）。按「上傳」才上傳；成功前狀態仍是「已存到本機」。也可選「先不要」。 |
| 3b | 首次登入：下載雲端存檔 | 帳號有雲端存檔、本機沒有 | 顯示雲端摘要，按「下載並繼續」才寫入本機（經保存埠）。 |
| 4 | 衝突 | 兩邊都有且修訂不同 | 並列兩份的上次保存時間與裝置、遊戲日、位元幣、夥伴／頭銜數，標出各自較多的一項，不替玩家判斷。選擇前暫停同步；沒選的一份留作備份。 |
| 5 | 同步狀態 | 狀態列 | 已存到本機／同步中／已同步／離線／同步失敗／需要選擇，六種各有字與形狀。 |
| 6 | 帳號選單 | 選單 → 系統區 | 遮罩顯示帳號、同步時間與這台裝置；提供「立即同步」（雲端版的手動保存）、切換帳號、登出。 |
| 7 | 切換帳號 | 帳號選單 | 有未同步變更時先同步或明示保留為本機備份；絕不讓 A 帳號的進度覆蓋 B 帳號的雲端存檔。 |
| 8 | 登出 | 帳號選單 | 不刪除任何存檔；本機保留一份可離線遊玩，不再同步。 |
| 9 | 同步失敗 | 上傳或下載失敗 | 先說本機是否安全，再說伺服器實際回的原因與下一步；可重試，連線恢復後自動重試。 |

「保存並結束」與本輪的本機自動保存都保留：雲端是加上去的一層，不取代本機保存。

## 5. 同步規格草案

**雲端信封**（伺服器只看信封，不解讀遊戲內容）：

```json
{
  "accountId": "<由登入供應商給的穩定 ID>",
  "saveId": "main",
  "serverRevision": 17,
  "contentHash": "sha256:<序列化存檔文字的雜湊>",
  "gameRevision": 342,
  "updatedAt": "2026-09-29T12:31:00.000Z",
  "device": { "id": "<本機產生的隨機 ID>", "label": "iPhone・Safari" },
  "summary": { "trainerName": "小光", "season": 0, "dayOfSeason": 2, "bits": 12450, "roster": 4, "titles": 2 },
  "payload": "<現有 championshipModernSave:v1 的完整文字>"
}
```

- `summary` 由客戶端從 payload 算出，只用於衝突畫面顯示；伺服器收到時可重算核對。
- **上傳**：`PUT /v1/saves/main`，標頭 `If-Match: <上次同步的 serverRevision>`。成功回 `200 {serverRevision, contentHash}`，客戶端確認雜湊相同後才顯示「已同步」；回 `409` 表示雲端已被別台裝置更新 → 進入第 4 畫面。
- **下載**：`GET /v1/saves/main` 回信封；寫入本機一律經現有保存埠與反序列化驗證，驗證失敗就不寫入。
- **衝突判定**：本機在上次同步後有變更，且雲端 `serverRevision` 不等於上次同步值 → 衝突。只有一邊變過 → 直接快轉（仍顯示結果）。
- **觸發時機**：本機保存成功之後（重要操作、離頁、換日、保存並結束），合併成最多每 10 秒一次的上傳；「立即同步」立即上傳。離線時只記「最新一份待上傳」，不累積操作清單。
- **備份**：每次衝突選擇與帳號切換前，伺服器保留被取代的那份（保留天數待 Owner 決定），帳號選單可查看與還原。
- **本機儲存鍵**：目前規則是單一存檔鍵、單一寫入者。同步中繼資料（`accountId`、上次同步的 `serverRevision`／`contentHash`、裝置 ID）若要寫在本機，需要新增第二個鍵或擴充存檔信封，兩者都要 Owner 同意並同步更新 firewall 測試；不能偷偷新增。

## 6. 安全與隱私

- 登入採 OAuth／OIDC 供應商；存取權杖放在記憶體或 httpOnly Cookie，**不放 localStorage**。
- 最少資料：只存帳號 ID、存檔信封與裝置標籤；不收聯絡人、位置或廣告識別碼。
- 需要隱私權政策、帳號刪除（連同雲端存檔）流程；玩家可能包含未成年人，需確認適用的年齡與家長同意規定（台灣個資法、目標市場法規）。
- 伺服器檢查存檔大小與信封格式；存檔內容仍由客戶端決定，雲端同步**不等於**防作弊，文件與介面都不做這種宣稱。
- 若日後上架 iOS App Store 並提供第三方社群登入，需同時提供「使用 Apple 登入」（網頁版不強制，但體驗建議一致）。

## 7. 需要 Owner 決定的事

| 決定 | 選項 | 建議 |
|---|---|---|
| 後端與費用 | Firebase（Auth + Firestore/Storage）、Supabase（Postgres + Auth + Storage）、Cloudflare Workers + D1/R2 + 自建登入、其他 | 先用 **Supabase 或 Firebase 的免費額度做 P1**：現成登入與儲存、亞洲區域可選、之後可依用量換方案。遊戲目前是 GitHub Pages 靜態網站，任何選項都是新的基礎設施與可能的費用。 |
| 登入方式 | Apple、Google、電子郵件魔法連結 | Google + 電子郵件先做；上架 iOS 前補 Apple。 |
| 資料區域 | 台灣／日本／新加坡 | 以主要玩家所在地決定，並寫進隱私權政策。 |
| 本機同步中繼資料 | 新增第二個 localStorage 鍵，或放入存檔信封 | 放入存檔信封（需一次存檔格式遷移與測試更新）。 |
| 備份保留 | 7／30 天、筆數上限 | 30 天、最多 5 份。 |
| 未成年玩家 | 年齡提示、家長同意 | 上線前由 Owner 與法務確認。 |

## 8. 分階段

| 階段 | 內容 | 風險 | 狀態 |
|---|---|---|---|
| P0 | 本機自動保存、真實保存狀態（保存中／已存到本機／保存失敗）、失敗重試、設計預覽、本規劃 | 低 | **本輪完成** |
| P1 | 登入＋**手動**上傳備份與下載還原（沒有自動同步）；首次登入匯入 | 低：玩家每次都自己按 | 待 Owner 決定後端 |
| P2 | 自動同步、衝突畫面、離線佇列、同步狀態列 | 中：多裝置情境 | P1 穩定後 |
| P3 | 帳號切換、備份清單與還原、帳號刪除、多裝置管理 | 中 | P2 後 |

每一階段都要：同步規則的單元測試（假伺服器，只在測試裡）；正常流程的瀏覽器驗收（隔離瀏覽器與測試帳號，不動玩家存檔）；斷網、逾時、409 衝突、伺服器錯誤的故障注入測試；實機驗收另列。

## 9. 驗收條件（P1 起適用）

1. 伺服器沒有回覆相同修訂與雜湊之前，畫面**不會**出現「已同步」。
2. 上傳途中斷網：本機存檔完好，狀態顯示「離線」或「同步失敗」，恢復後自動完成。
3. 兩台裝置交錯遊玩：一定出現第 4 畫面，不會自動覆蓋；沒選的一份可從備份還原。
4. 切換帳號或登出：不會把一個帳號的進度寫進另一個帳號。
5. 下載的存檔一律經現有反序列化驗證；格式錯誤時不寫入本機並說明原因。
6. 全程沿用單一保存埠；firewall 測試的鍵數與寫入者規則若要改，必須先有 Owner 決定並同步更新測試。
