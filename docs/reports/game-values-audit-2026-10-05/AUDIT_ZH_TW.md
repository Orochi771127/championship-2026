# 遊戲數值接線盤點（2026-10-05）

依 [Owner Direction 2026-10-05](../../coordination/OWNER_DIRECTION.md)「先做完整盤點表」。本表依 `main`（`14ed0a7e`）的程式、`docs/contracts/championship/` 的合約與原作證據查詢工具整理。每一項都對照過目前的程式碼，不照抄較舊的合約或狀態表。

## 結論

- **「個性、進化條件沒接上」不正確。** 兩者都讀原作資料運作，依據見第 2 節。
- **玩家看得到的空白只有兩個：** 馴獸師資訊的「地圖完成度」與「遊玩時間」。原作寫入這兩個值的程式還沒追到，所以畫面顯示 `---` 與 `--:--`，沒有用猜的數字填。
- **真正的缺口是特定分支，不是整個系統。** 牧場、照顧、訓練、進化、狩獵、戰鬥、商店、時鐘的主要規則都已依原作移植（各模組開頭記有 ROM 位址）。還沒追到的是第 3 節列出的特定情境；程式碰到這些情境會停下來報錯，不會自己編規則。
- **另有一批是「已實作、但還沒和原作逐一比對」**（第 4 節），影響的是確認程度，不是有沒有數值。

狀態用語：

- **ROM 驗證**：數值或規則由原作 ROM 的程式碼或資料表取得，並以原作 CPU 執行結果比對過。
- **部分**：主要路徑已移植，仍有分支或比對未完成。
- **未追**（`UNKNOWN_REQUIRES_TRACE`）：原作怎麼做還不知道。程式維持中性或拒絕執行，不猜。
- **產品自訂**：原作沒有或不適用、由產品決定的部分，例如名稱標籤、介面。

## 4. 已實作、但還沒和原作逐一比對的

這些都有數值、會運作，缺的是「和原作畫面或執行逐一比對」的驗收：

- **戰鬥：** 595 個招式腳本都能執行，但「AI 自然選招」與每招畫面還沒逐一比對。原作的出場、返回待機與攝影機也是部分完成。
- **角色行為：** 15 個工作流程中，14 個為部分完成（`CHARACTER_BEHAVIOR_RESTORATION_STAGE.v1.json`），例如各物種與個性組合、進化提示動作 `+454`、音樂狀態的呼叫端。
- **開場故事：** 流程已接上，畫面與聲音的一致性為部分。
- **實機：** 全部系統都還沒有實機驗收。

## 5. 建議的追蹤順序

1. **馴獸師資訊的兩個空白。** 玩家直接看得到，範圍小。
2. **一天結束的寫入順序。** 影響每天的成長結果。
3. **傳送門晝夜與解鎖類型。** 影響能去哪裡、遇到什麼。
4. **自有隊伍的對戰模式與賽後寫回。** 影響能不能用自己培育的數碼獸打所有比賽。
5. **「服從」是否真的存在。** 先用證據確認原作有沒有獨立機制，再決定要不要實作。
6. **狩獵的伴隨角色、野生互鬥與其他捕獲路徑。**

每一項都照 **證據 → 合約 → 實作** 的順序：先用原作證據查詢工具（`championship-evidence`，已接上 Claude Code）找到原作程式與資料，寫進合約，再實作與測試。找不到證據的維持未追。
