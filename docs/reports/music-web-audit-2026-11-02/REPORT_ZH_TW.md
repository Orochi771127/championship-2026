# 全遊戲音樂網頁品質審查（2026-11-02）

## Owner 指示

> 我用在設施配置的音樂應該是一首叫 podium metry……你再幫我把所有遊戲中的音樂都審查一次，要確認都是適合網頁遊戲的音質跟檔案。

範圍是 26 個音樂 cue，共 30 個音檔：22 首 MP3，加上對戰決賽與勝／敗／和局用的 4 組 OGG + M4A（8 個檔）。原始量測數據在 `AUDIT.json`。

## 結論

| 項目 | 結果 |
|---|---|
| 格式 | 合格。MP3 為 128 kbps CBR、44.1 kHz 立體聲；OGG Vorbis 與 M4A AAC 為 48 kHz，各瀏覽器都能播 |
| 檔案大小 | 合格。最大 3.75 MB（南方港灣樞紐），音樂總計 50.5 MB，各場景只會在進入時載入自己的那一首 |
| 中繼資料 | 合格。沒有內嵌封面圖，沒有多餘的標籤 |
| 播放響度 | 合格。循環 BGM 的投射響度都在 -24.0 到 -25.0 LUFS，結果音效在 -24.9 到 -25.5 LUFS |
| 播放峰值 | 合格。投射 true peak 全部 ≤ -6.9 dBTP |
| 檔案本身峰值 | 輕微。10 首場景 MP3 的檔案 true peak 在 +0.1 到 +0.8 dBTP。執行時會先降約 11 dB，瀏覽器也用浮點解碼，所以不會聽到破音。重新編碼 128k 會再損失一次音質，所以不改 |
| **循環接縫** | **有問題，本批已修正**（見下節） |

## 循環接縫問題與修正

只修改 cue 的剪裁與循環參數，沒有重新編碼任何音檔，所以音質零損失。

### 1. 用真正的重複段做無縫循環

第一圈從頭播一次，之後在量到的重複點換手。

| 曲目 | 用途 | 重複間隔 | 換手 → 接回 | 交叉淡化 | 接縫相關（前／後） |
|---|---|---|---|---|---|
| 幾何舞台 Podium Geometry | 設施配置 | 39.02 s（約 123 BPM 的 20 小節） | 52.15 → 13.126 s | 0.1 s | 0.84 / 0.83 |
| 熔岩突破 | 對戰場地 2 | 45.00 s | 117.55 → 72.55 s | 0.05 s | 0.91 / 0.95 |
| 地獄超速 | 對戰場地 7 | 60.00 s | 81.67 → 21.67 s | 0.1 s | 0.83 / 0.83 |
| 石緣交鋒 | 一般對戰場地 | 108.0 s | 174.82 → 66.82 s | 0.1 s | 0.80 / 0.81 |

**Podium Geometry**：Gemini 說這首是 120 BPM、從 8 秒循環到 56 秒。在那個 48 秒間隔上，波形相關只有 0.19，9 個 1 秒區塊沒有一個對得上，所以這個說法不成立。實測速度約 123 BPM，真正的重複間隔是 39.0245 秒（20 小節）。

**石緣交鋒**：原本是從全音量的結尾直接淡入安靜的前奏，現在改成在重複段裡循環。代價是原曲 175 秒之後的收尾段不會再播到。

### 2. 剪掉結尾靜音

這幾首找不到可靠的重複段（接縫相關 0.12–0.78），所以改為剪掉每圈結尾的空白。

| 曲目 | 原本每圈的靜音 | 修正 |
|---|---|---|
| 烽火同心 | 約 1.8 s | trimEnd 2.6 |
| 翠緣交鋒 | 約 1.9 s | trimEnd 2.75 |
| 南極圍攻 | 約 1.9 s | trimStart 0.17、trimEnd 2.66 |
| 泰坦終擊 | 約 1.5 s，開頭還有 0.48 s 靜音 | trimStart 0.46、trimEnd 2.65 |
| 競技場蜃景 | 約 0.8 s | trimEnd 2.16 |
| 聯邦圍城 | 淡出尾端約 0.9 s 近無聲 | trimEnd 0.94 |
| 靜夜修練 | 淡出尾端約 0.5 s 近無聲 | trimEnd 0.47 |

修正後，每首結尾的最後 0.8 秒會直接與開頭交叉淡化，不再有空檔。

### 3. 不需修改

- 九首原創場景曲：中央輝光核心、東方秘境群山、空靈月湖畔、林卡拉慢拍、啟程之頁、北境翠綠平原、東南熔爐丘陵、南方港灣樞紐、西南潮汐邊境。它們的開頭和結尾在 2026-10-18 已依量測剪裁過，換手點都落在 -33 到 -58 dB 的安靜段，沒有空白。這幾首是氛圍曲，重複段不明顯（相關 0.4–0.83），所以維持「淡出後重頭」的循環方式。
- 錦標賽決戰：32 秒的原生循環 OGG，按設計就是無縫循環。
- 勝／敗／和局：4 秒左右的短音效，不循環。
- 幸運抽獎櫃檯、甜蜜升級：今天稍早已用量測的循環點上線。

## 同時修正的播放器問題

審查時發現，換場景時的淡入淡出時間，原本取的是新曲自己的循環交叉淡化時間。幸運抽獎櫃檯（0.05 s）和甜蜜升級（0.1 s）都已上線，所以目前進商店、選狩獵場、狩獵設定和對戰選單時，音樂幾乎是硬切的。

修正後：
- 每圈循環的換手，用 cue 自己的短交叉淡化。
- 換場景時恢復原本的 0.8 s。原生循環曲（交叉淡化為 0）維持 0.35 s。
- 舊程式在新增的測試上會失敗，新程式則通過。

## 量測與驗證

- Chrome 實機用遊戲本身的播放器測量循環換手。四首音樂循環與理想間隔的誤差在 10–22 ms：
  - 幾何舞台 39.003 s，理想 39.0245 s
  - 熔岩突破 44.978 s，理想 45.0 s
  - 地獄超速 59.98 s，理想 60.001 s
  - 石緣交鋒 107.99 s，理想 108.0 s
  - 這屬於 HTMLMediaElement 的正常抖動，落在 0.05–0.1 s 的交叉淡化範圍內。
- 泰坦終擊實測從 148.29 s 換手回 0.48 s，中間沒有靜音。
- 音樂瀏覽器 gate 通過：每首場景曲在真的 Chromium 解碼後，都回到正確的循環起點。
- 尚未做人耳試聽驗收。
