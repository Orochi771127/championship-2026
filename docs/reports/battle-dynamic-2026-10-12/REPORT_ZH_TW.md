# 對戰動態演出：原作比例＋動態鏡頭＋技能與場地互動（2026-10-12）

基準 `b39a9cd6`，獨立 worktree 分支 `feat/battle-dynamic-fx-2026-10-12`。Owner 已授權自審後 commit、push、整合進 `main` 並發布（見第 5 節）。依 [Owner Direction 2026-10-12](../../coordination/OWNER_DIRECTION.md)：Owner 以兩段競技場同人遊戲錄影為參考，要求「用我們自己的角色與招式絕招」做出同樣的動感，並定下最新方向：

- 角色維持原作相對大小，取消對戰 1.5 倍；
- 動感靠鏡頭拉近、拉遠與跟拍，加上既有技能特效與場地互動；
- 互動要對準真正的出招位置、命中點與地面；
- 只做視覺演出，傷害、碰撞與勝負規則不變。

## 1. 做了什麼

| 項目 | 內容 | 位置 |
|---|---|---|
| 原作比例 | 動態演出下，完成的原創角色以原作相對大小繪製（不再 ×1.5），density-4 原圖解析度不變。`?battleFx=classic` 保留舊的固定全場畫面與 1.5 倍以供比較 | `createBattleFieldPixiPresentation.js` |
| 動態鏡頭 | 沿用既有 Pixi world 容器，不新增 ticker。行為依序為：開場先全景，再推近；平時框住所有站立角色；技能出招推近出招者與對手；絕招先推近出招者再拉遠，看清整段路徑；投射物飛行時跟拍；重擊時 punch 與震動；擊倒時鏡頭停在倒下者，再拉回 | `battleFx/battleFxCamera.js` |
| 跟出場外 | 原作移動會讓角色走出場地圖。鏡頭照樣跟過去，場外用 8 片鏡射、逐步變暗的場地延伸補上（掛載時算一次，每幀無成本），接縫連續 | 同上＋場景 |
| 技能與場地互動 | 起跑與跑動揚塵、落地揚塵圈、出招點閃光、命中點火花、地面衝擊波環、會落地彈跳的碎屑、2–3 秒的短暫焦痕、爆炸收尾 | `battleFx/battleFxLayer.js` |
| 對準位置 | 出招點取招式特效實體的第一個位置。命中點依序取原生命中火花、投射物最後位置，最後才用身體朝攻擊方的一側。地面取原生地面 y（去掉高度）或角色站點。實錄 1v1：23／23 次命中都對到原生命中點 | 同上 |
| 拿掉的東西 | 身上的光暈與氣場、自繪光束、投射物頭部大光球都移除；角色身上只保留短暫的命中閃白 | — |
| 文字 | 「對戰開始！」、K.O.!、重擊／命中／會心一擊、招式欄、紀錄列，五語翻譯（英文用短詞，例如 FIGHT!、SMASH!）。招式欄與紀錄列**只顯示核准名稱**：30 個特殊技能沿用既有的五語核准名；物種招式尚未核准，所以顯示「角色名＋技能／絕招」（例：「赤曜槍皇發動絕招！」）。本機 `?battleFxDebug` 驗收時改顯示穩定技能 ID | `uiText.*.js`、`app/battleFxLookups.js` |
| 招式外觀 | 招式的視覺類型（近戰、投射、光束、吐息、範圍…）由特效圖組名稱判斷，顏色由屬性選擇器推論；每個角色最強的技能就是它的「絕招」。這些都只是演出分類，不是招式名。名稱候選另見[招式名稱盤點與待審候選](../battle-move-names-2026-10-12/REVIEW_ZH_TW.md)，核准後寫進 `BATTLE_FX_MOVE_NAMES` 才會顯示 | `battleFx/battleFxRecipes.js`、`app/battleFxLookups.js` |
| 版面 | 對戰場地佔畫面大部分（最高約 1.22 倍寬），隊伍列各一行，空格不顯示，剩餘高度給紀錄列 | `vs5Styles.css` |
| Owner 自己的特效 | 本機（loopback）預設載入 Owner 的原創共用特效包（210 格／26 組）。此包原本在 `main` 沒有註冊，所以從未載入；本批補上同一筆 LOOPBACK_REVIEW_ONLY 註冊。特效檔本身是私有審查素材（`isPrivateRepositoryPath`），照舊只留在本機，不進版控、不發布。`?vfxOriginal=off` 可關閉 | `ART_PRODUCTION_INDEX.json` |

## 2. 順手修正

- `battleRuntime` 的 `flash.active` 在第 0 幀誤判為真（`-1 === 0-1`），只要開戰前多畫一幀，Three 疊層就會整片閃白。改成只有真正命中後才為真；只影響演出旗標，模擬不變。
- 地面陰影傳入已改名的 `facing`（本機 review 路徑會每幀拋錯），改傳實際繪製方向。另一個工作階段也在修同一行，合併時以其中一版為準。

## 3. 規則不變的證據

- 新測試 `tests/championship-battle-dynamic-fx-cases.mjs`（11 項）。用同一場完整對戰比較「有／無演出讀取」，每幀 HP 與結果完全相同；另含絕招唯一性（204 個出戰物種各 1 招）、事件追蹤、鏡頭推近／拉遠／跟拍、命中點優先序、五語文字齊備、只顯示核准名稱、驗收時顯示技能 ID。
- `test:ci`：1,703 項中 1,702 通過。唯一失敗是 `championship-loading-optimization-cases` 的打包測試：本機沒有安裝 `esbuild`，在 `main` 本機同樣失敗，與本批無關。另外調整了既有的掛載沙盒測試，補上新的 `BATTLE_DYNAMIC_FX` 與 `activeRuntime` 兩個沙盒變數。

## 5. 限制

- 只在本機（loopback）驗證，未做實機、真機 FPS 與 WebGL 遺失測試。無頭 Chrome 用 SwiftShader，畫格時間沒有參考價值。
- 招式名稱是通用組字，不是原作招式名，也不是 Owner 命名。
- 依原作 AI，普通攻擊約佔八成，絕招出現頻率由原作決定。
- 發布範圍只有程式碼與文字；Owner 原創特效包仍是 LOOPBACK_REVIEW_ONLY，不會進入公開建置，因此公開網站的對戰特效沿用既有公開素材。
