# 陪練三連戰試玩包（約 8 人，探索性）

> 用途：檢查同一個循環在真人身上是否成立。循環是：同一隻拍檔 → 換或保留作戰方針 → 自動戰鬥 → 看懂這場發生了什麼 → 自願再試另一種做法。
> 規模：約 8 人，只用來找出循環斷在哪裡，不用來宣布留存率提升多少。
> 前提：試玩用的版本已經部署到試玩者能開的網址。目前程式只在本機的 worktree 裡。

## 1. 兩個版本

兩個版本只差在結算畫面的一頁「作戰紀錄」。戰鬥、對手、獎勵和陪練畫面完全相同。

| 版本 | 網址參數 | 結算畫面 |
|---|---|---|
| A：基本結果 | `championship.html?playtest=1&tacticRecord=off` | 勝負、獎金、同步經驗等原本就有的頁面 |
| B：加上因果 | `championship.html?playtest=1` | 多一頁「作戰紀錄・這場打法」，3–6 行短數字：出手、招式、走位比例、用到的招式；SP 用光或倒下的秒數只在真的發生時才出現；另外有「上次「另一種方針」」的對照 |

- `?playtest=1` 會在陪練分頁顯示「下載試玩紀錄」。紀錄只存在記憶體裡，不寫進存檔。重新整理頁面就會清空，所以每位試玩者結束時都要先下載。
- 一半的人先玩 A，另一半先玩 B。兩段的對手組合也要對調先後，例如第 1、3、5、7 人用 A 開始。
- 判讀「第一次看不看得懂」時，以第一段為主。第二段的表現好，可能只是因為已經學過規則，不能直接算在版本上。

## 2. 流程（每人約 15 分鐘）

1. 用測試存檔進入遊戲，依序點「對戰 → 征途 → 陪練」。
2. 第一段（6–8 分鐘）：選一隻拍檔，打完三場。試玩者自己決定換不換方針，主持人不給提示。
3. 第二段（6–8 分鐘）：換成另一個版本，再打一輪。
4. 在問任何「下一局想試什麼」之前，先讓試玩者自己決定要不要點「再來一輪」，並記錄這個決定。
5. 最後才進行訪談（見第 4 節），然後下載試玩紀錄。

## 3. 觀察表（每場一列）

| 欄位 | 怎麼記錄 |
|---|---|
| 場次／版本 | 1–3／A 或 B |
| 當時可選的方針 | 一律是三選一，再記下上一場用的是哪個 |
| 選了什麼 | 必殺優先、普通攻擊或支援優先，以及是不是維持原本的 |
| 試玩者說的預期 | 開打前主動說出口的話，照原話記 |
| 實際觸發了什麼 | 照抄下載紀錄裡 `local[].counts`、`decisions` 和 `firstSkillAt` |
| 試玩者對戰果的解釋 | 結算畫面時或結束後說的話 |
| 有沒有自願開始下一場或下一輪 | 有／沒有，以及花了多久才決定 |
| 下一場實際的做法 | 換成哪個方針，以及理由 |
| 有沒有提到「牠」做過的具體事 | 照原話記下，例如「牠剛剛一直在繞」 |

## 4. 中立提問（不要把答案告訴試玩者）

- 「你剛才預期什麼會改變？」
- 「你覺得這場結果主要是怎麼發生的？」
- 「換成這個對手，你會怎麼準備？」
- 不要問「你有看到方針讓牠更常用招式嗎？」這種會引導答案的問題。

## 5. 判讀表

| 看到的現象 | 下一步 |
|---|---|
| 不管選哪個方針，紀錄都差不多 | 先修規則：方針的效果太小或代價不明顯 |
| 紀錄有差異，但試玩者說不出原因 | 修畫面：要把哪一行放大或移到前面 |
| 看懂了，但沒有想再試的計畫 | 檢查是不是只剩一個正確答案（見量測報告的「固定答案」風險），或三種對手的差異不夠 |
| 只對結晶或數值有興趣 | 把成長動機和策略動機分開評估 |
| 記得戰術，但完全不在意這隻拍檔 | 保留有效的戰鬥改進，先不宣稱拍檔關係已經成立 |
| 試玩者覺得「牠很笨、牠沒用」 | 檢查規則可靠性，以及畫面和角色行為是不是互相矛盾（例如支援優先下 4–5 成的判斷都在走位） |
| 會再試，也說得出和這隻拍檔的共同經歷 | 支持往下做行為卡、個性方針等後續項目 |

## 6. 紀錄格式

`下載試玩紀錄` 輸出一個 JSON 檔：`{exported, variant, entries[]}`。每個 entry 是一場戰鬥：

- `context`：`{series:'PRACTICE', bout, tactic, won}`。
- `outcome`、`seconds`。
- `local[]`：每隻拍檔的 `tactic`、`profile`、`counts{normal,skill,support}`、`moves[]`、`decisions{total,attack,reposition}`、`firstSkillAt`、`spEmptyAt`、`downAt`、`hpLeftRatio`、`damageDealtRatio`。
- `shownLines`：B 版畫面上實際顯示的文字。A 版是空陣列。

這些數字都是戰鬥 runtime 一邊打一邊直接記下來的，和結算畫面讀的是同一份資料。
