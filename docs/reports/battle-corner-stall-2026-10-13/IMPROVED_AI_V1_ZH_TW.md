## 1. 改了什麼

程式：[`src/championship/battle/battleAiAdaptation.js`](../../../src/championship/battle/battleAiAdaptation.js)。它在原作 state 4／5 處理函式之後執行。

| 條件（全部成立才動作） | 動作 |
|---|---|
| 仍在 state 4／5，且有目標 | — |
| 通知是站立類（1，或已播完的 8–12 攻擊／輔助姿勢）；不在受擊、倒地、復起（15、18–21）；沒有負面狀態；有走速 | — |
| 在原作死區內：距離 < 48 px，且「≥ 32 px」或「縱向」 | — |
| 依原作規則閒置滿 20 個戰鬥時鐘幀 | 發出原作的走路通知 7，朝原作處理函式本來就瞄準的點（目標旁 16 px）走 |
| 該點在 x 夾限 32–384 之外（目標貼牆） | 改瞄目標另一側的同一點；走路中也維持可到達的瞄準 |
| 同一次決策已介入 3 次 | 不再介入，交回原作 |

- 是否出招、射程與縱向規則，仍由原作處理函式決定。
- 不抽亂數，不讀未來亂數，也不讀對手尚未公開的決策。
- 不改冷卻、硬直、速度、攻防、SP、傷害或勝負。
- 沿用既有戰鬥時鐘，沒有新增 ticker。
- 雙方都使用同一套規則。

### 其他驗收項目

- **四角與場邊**：
  - 原作的長停頓有一大部分發生在場邊。正常遊戲 n6 是左牆，n3 是右牆。
  - 改良 AI 遇到牆邊目標時，會繞到可到達的一側。
  - x 夾限外的位置在兩種 AI 下都會出現，最多 2.95 px（原作）／2.81 px（改良）。來源是原作 0210F5D8 的 16 px 互推，在夾限之後才執行，不是穿牆，改良 AI 也沒有讓它變多。
- **長硬直、連續擊退、倒地**：受擊、倒地、復起通知時一律不介入（有單元測試）。被打時不會比原作更早行動，也不會因此變成無敵。
- **目標倒地或失效**：沒有目標時不介入，交給原作重新決策。目標在出招當幀被清空的情況，已由原作復原修正處理。
- **輔助招式**：已播完的輔助姿勢（通知 12）與攻擊姿勢一樣視為站立；未播完的姿勢不介入。
- **出招距離與方向**：仍完全由原作處理函式判斷，量測結果 0 次超射程、0 次縱向出招。

## 4. 已知限制

- 物種 0–7 走速為 0，這是原作資料，仍會停住。改良 AI 不替牠們加速。
- 3v3 有 5/60 場勝方與原作不同。原因是消除對峙後戰局本身改變，雙方規則相同，A:B 勝場沒有偏向任何一方。
- 沒有實體手機驗收；正常遊戲錄影是 headless Chromium。
