## 2. 根因

### A. 移植錯誤（已修）：目標在出招同一幀被清空，角色卡在出招狀態 14

**原作流程（OVL19）**

| 位址 | 行為 |
|---|---|
| 02116B10 `bl 0x0210F8C4` | 從攻擊物件池配置，不讀目標 |
| 02116B68 `ldr r3,[r5,#0x5C]` | 把目標物件傳給初始化函式 |
| 0211C098 `movs r4,r3`、`moveq r0,#0`、`popeq` | 目標為空就回傳 0，不進 C144 守門，也不扣資源 |
| 02116B78 → 02116C24 | 清掉物件 bit0、清空攻擊槽，回到 state 1 重新決策 |
| 02116B20 → 02116C5C | 只有物件池配置失敗時，才在 state 14 等目前動畫結束 |

- state 15 同樣在 02116D68 傳入 +0x5C。
- state 16 在 02116F34 傳入的是 +0x64。

**移植版的差異**

- `battleRuntime.allocateAction` 在 `targetSlot<0` 時直接回傳 null，而原作的配置函式不看目標。
- 結果流程走到原作「物件池滿」的分支：等目前動畫結束。
- 若角色當時在走路（通知 7，循環動畫），動畫永遠不會結束。角色便沿原方向走到場邊，停在角落，直到整場結束。

**重現案例**

- 種子 24 練習對戰。影脈槍兔 slot5 在 clock 180 走到距目標 32 px；同一幀目標被隊友擊倒，+0x5C 被清空。
- 之後在 (32, 256) 角落停 1307 幀。
- 瀏覽器正常畫面的同一固定種子也重現了；修正後同一場不再停住，並在 clock 993 結束。

**最小修復**

- 正常流程的配置只看物件池。
- 初始化在目標為空時拒絕：記錄 `LAUNCH_REFUSED`／`NULL_TARGET_0211C0A0`，不扣資源。之後由既有流程釋放攻擊槽、回到 state 1。
- 沒有改動硬直、速度、攻防、SP 或勝負。

**回歸測試**：[`tests/championship-battle-null-target-launch-cases.mjs`](../../../tests/championship-battle-null-target-launch-cases.mjs)。修正前失敗（state 14 連續停留超過 1000 幀），修正後通過。

### B. 原作行為（未改）：接近狀態的死區

- state 4／5（021161F0／02116314）每 4 幀做一次判斷：
  - 距離 ≥ 48 px：通知 7，開始走路；
  - 非縱向、距離 < 32 px、且有空的攻擊槽：發動；
  - 其他情況：只更新朝向，不改通知。
- 角色若剛被打、剛復起或剛攻擊完，通知是 1、8、9 或 12，速度為 0。這時落在「32 ≤ 距離 < 48」或「縱向且距離 < 48」，就既不走也不打。
- 冷卻用完後，AI 決策表（021159D4）不看距離，常常又選回 state 4。
- 只有擲到移動決策（state 3）或被別人撞開時，才會解開。

**CPU 對照**

- [`scripts/research/trace-battle-corner-stall-cpu.py`](../../../scripts/research/trace-battle-corner-stall-cpu.py) 把擷取到的四組實際輸入交給原作 021161F0、02112DCC、02112A18 執行，結果在 [BATTLE_CORNER_STALL_CPU_2026-10-13.json](../../research/BATTLE_CORNER_STALL_CPU_2026-10-13.json)。
- 原作同樣沒有通知、沒有發動、位移為 0；對照組（48 px、31 px、冷卻 0）分別得到通知 7、state 14、重新決策。
- 移植版對同一輸入 7/7 相符。

**信心與界線**

- 處理函式本身：`VERIFIED_BINARY`（受控 CPU）。
- 「原作整場對戰也會在角落停這麼久」：`UNKNOWN_REQUIRES_TRACE`。目前沒有可用同隊伍、同場地的原作整場模擬器錄製，不以移植版結果反推。

這一項留在原作模式，由另行標示的 Owner 授權改良 AI 處理。

### C. 獨立缺陷（找到重現、根因未定、本輪不修）：必殺技開場演出時間軸不一致

- **現象**：種子 2 的 3v3 在 clock 1228 拋出 `BATTLE_RUNTIME_PRELUDE_NATIVE_TIMELINE_MISMATCH`。
- **條件**：slot2 的招式 435 開場演出播完時，其腳本仍在 `PRELUDE` 階段；同時 slot3 也處於獨占演出。
- **瀏覽器影響**：例外會從 Pixi ticker 的 `advance` 拋出，每幀重拋，整場畫面凍結，不會自行恢復。
- **頻率**：固定種子 3v3 30 場中 1 場。
- 需要另外追「兩隻同時獨占」的原作規則，才能修。

### D. 原作資料（非錯誤）

- 物種 0–7（數碼蛋與幼年期）的戰鬥走速、跑速在 `BATTLE_SPECIES_MOVEMENT` 為 0。
- 因此牠們會播走路動畫但位置不變。
