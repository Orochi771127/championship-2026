# 視覺與動效規範：「晴空競技」與演出層（2026-10-15）

> 範圍：全遊戲 UI／HUD 的配色、元件與重要時刻演出。角色、動畫、棲地、地圖、玩法、數值、進化條件、捕獲判定、獎勵結算與存檔格式**不變**。
> 本文件所有呈現變更屬 `OWNER_APPROVED_ADAPTATION`（呈現層），依 2026-10-15 Owner 指示；不是原作證據。
> 延續 2026-09-29「數位生態箱」設計系統（[DESIGN_ZH_TW.md](../ui-redesign-2026-09-29/DESIGN_ZH_TW.md)）的 token／元件／回饋分級架構，只新增一套配色、一個招牌元素與一層演出。

## 1. 方向：晴空競技（Arena Daylight）

Owner 要求「明亮、俐落、有輕科技感與世界觀辨識度」。玩家第一眼看到的是標題主視覺：晴空、象牙白石材、**青綠色網路線（Logo 的 cable）**與**冠軍金盃**。新配色把這四個元素帶進每個畫面：

| 元素 | 來源 | 在介面上的工作 |
|---|---|---|
| 晴空底 `#eef5fa` ＋ 4% 青綠細格線 | 標題天空 | 所有系統頁的地面；格線是「輕科技」的唯一紋理 |
| 白色 HUD 浮島 `rgba(250,253,255,.94)` | 象牙石材 | 疊在牧場／狩獵／對戰場景上的面板，不做背景模糊（效能規則沿用） |
| 青綠 `#087a8c`（文字可讀）／`#19c3d3`（僅裝飾） | Logo 網路線 | 唯一「可以按／已選取」色；光環、連結線 |
| 金 `#e2a21f`／`#875600`（文字） | 金盃 | 只給位元幣、獎勵、徽章 |
| 深海軍藍墨 `#0d2638` | — | 主文字；不用純黑，像素角色保有自己的最暗值 |

- **預設主題**改為晴空競技。偏好檔只儲存「非預設值」，所以從未改過主題的玩家（含 Owner）會直接看到新配色；明確選過藍白清爽／經典暖黃／復古藍金的玩家維持原選擇。「跟隨系統」：深色→深色夜景，淺色→晴空競技。
- 對比（WCAG 2.x，由 `tests/championship-settings-cases.mjs` 驗證）：主文字對底 14.1、次要 7.4、說明 5.4；強調色對白卡 5.0、白字在主按鈕 5.0；所有狀態色對白卡 ≥ 5.0。

## 2. 招牌元素

1. **像素階梯**（沿用）：區段小標、選取卡、演出銘牌右上角（金色）。
2. **連結線**（新增）：頁面標題下一段 54px 青綠纜線＋發光節點，呼應「網線拍檔」。只出現在頁面主標題，復古藍金主題不套用。
3. **遊戲按鍵**：主要動作按鈕上亮下暗、底部 3px 唇緣、按下下沉 1px（`--btn-primary-bg`／`--btn-primary-edge`），字落在強調色中段，對比等同強調色本身。

| 等級 | 何時 | 長度（完整／省電） | 是否攔截操作 |
|---|---|---|---|
| 日常 | 按下、切工具、開選單 | 120–200ms（沿用） | 否 |
| 確認 toast | 捕獲成功、對戰開場 | 1.9s／1.4s；1.3s／0.9s | **否**（場景照常可操作） |
| 揭曉 reveal | 狩獵結算 | 1.4s／0.7s | 第一次點擊＝立刻落定，且該次點擊不會按到下面的按鈕 |
| 重要時刻 moment | 傳送門連線、徽章獲得、進化揭曉 | 1.5s／0.9s；2.6s／1.6s；2.8s／2.0s | 第一次點＝落定，第二次點／Esc＝關閉；時間到自動關閉 |

### 4.1 起承轉合（以徽章為例）
1. **起**：背景以主題地色蓋上一層帷幕，中央金色光暈亮起。
2. **承**：徽章由 −540° 旋轉入場並微微放大（900ms）。
3. **轉**：金色光環擴散、16 顆碎光四散（省電模式不畫）。
4. **合**：銘牌彈出「徽章獲得／頭銜名」，合成號角音效收束；畫面停在完整構圖等待點擊。

### 4.2 各演出內容

| 演出 | 觸發（只讀已決定的狀態） | 內容 |
|---|---|---|
| 傳送門連線 | 狩獵場畫面掛載、下載中 | 光核膨脹、光束落下、三道光環、銘牌「傳送門連線／場地名／限時 08:00」；場地就緒且至少顯示 0.9s 後開場（減少動態時就緒即開）。互動教學不播放（保留教學自己的流程） |
| 捕獲成功 | 記憶卡上出現新的條目（`huntField.hud.onCard` 唯讀投影） | 光環＋碎光、銘牌「捕獲成功／種名／已收入記憶卡·N」 |
| 收穫揭曉 | 狩獵結算畫面 | 記憶卡框掉落、背後光芒、光帶掃過，名稱與名單依序升起 |
| 徽章獲得 | 對戰結算翻到原作的 `result_sub_titleget` 頁 | 見 4.1；徽章圖延遲載入時先顯示中性金盤，載入後替換 |
| 進化揭曉 | 原生進化序列（ROM 時序、環／光／文字）**結束後**，且沒有換日、確認或信件佔用畫面 | 新型態頭像（整數倍放大保持像素格）、光芒、銘牌「進化／種名／某某進化成了某某」 |
| 對戰開場 | 對戰場地就緒 | 我方／對手兩側滑入、VS 徽記落下；位於上緣，不遮住原作「準備！／開戰！」 |

## 5. 技術規則（效能與正確性）

- **只裝飾、不決定**：所有演出只讀 app 已寫好的資料；不寫狀態、不延遲任何狀態變化；場景從第一幀即在底下運作。
- **略過永遠完整**：每個動畫部件的靜態樣式就是最終狀態，keyframes 只描述「從哪來」；略過＝`animation: none`。
- **沒有第二個迴圈**：不使用 `requestAnimationFrame`、不新增 Pixi ticker；CSS 動畫只動 `transform`／`opacity`，沒有無限循環。唯一計時器是結束本次演出的 `setTimeout`。
- **減少動態**：不位移、不縮放、不旋轉、無粒子，只有 160ms 淡入淡出；不播音效。
- **省電（畫質「省電」）**：不畫碎光、光芒與額外光環，長度縮短；文字與資訊完整。
- **背景分頁**：分頁隱藏時立即落定並結束，不在背景空轉。
- **釋放**：畫面離開即 `dispose()`：移除節點、清除計時器與監聽、淡出音效。
- **音效**：`presentation/ceremony/ceremonyAudio.js` 以振盪器＋短噪音即時合成，經既有音效匯流排的 sfx 類別（靜音、主音量、音效音量都生效）；瀏覽器尚未允許播放時直接靜音，不排隊。
- **層級**：toast `--z-toast`；moment／reveal `--z-lifecycle`；傳送門在狩獵視窗內 z=6（載入卡片 z=7 疊在其上）。
