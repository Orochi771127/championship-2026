## 操作與按鈕位置

手機：左下空白區拖曳移動；右下 **76px 普攻**按住連續攻擊，鬆開停止。周圍三個 **58px 技能**點按施放；**60px 強力技**與 **54px 閃避**在上側，**68×48px 換角**獨立在左側。右側空白區可以拖曳手動瞄準。HP／TP 數字在左上各自的條內；按鈕顯示 TP 消耗或冷卻秒數。暫停為右上 44px。

桌面：WASD／方向鍵移動；左鍵、1 或 J 普攻；右鍵／2、Q／3、E／4 施放三技能；R 強力技；Space／Shift 閃避；X 換角；Esc／P 暫停。

UI 參考只讀取同版本來源 `client/touch.css`：左移動、右下招式、安全邊距與冷卻數字。來源是 2×2 卡片；本產品依普攻／三技能／強力技配置重新寫成弧形控制，沒有複製來源樣式程式。套用 game-ui-frontend 與 web-game-foundations 技能，維持 DOM HUD 與既有 Pixi 場景的分工。

## 動作完成程度

196 隻都可使用目前核准的 runtime 圖集與招式配置；這不是宣稱 196 隻的新動作已逐隻完成驗收。034、064、061 已實際檢視既有施招槽位；其餘 193 隻依九種體型配置可玩的暫用動作，保留 `PROVISIONAL` 狀態。配招與體型歸類依本產品既有角色資料，不導入來源角色編號或名稱。

來源三種體型 × 七段 walk／attack／shoot／special／charge／hurt／faint × 八方向，已按原生 ticks 慢速播放，記錄 1,352／1,352 個槽位。其他來源候選未播放者仍標 `CANDIDATE_ONLY_NOT_YET_PLAYED`，不把靜態檔案存在當作動作驗收。來源重複圖片不代表槽位可合併；runtime adapter 保留 ticks、anchor、offset、hitFrame／release 對應。

完整八方向新畫稿、逐隻精修與正式招式特效仍待 dot／美術交付及核准；本次未重畫、覆寫或提升待修稿。現有圖像主要沿用左右面向，八方向邏輯以方向指示呈現。程序特效與合成音效是已接入的原創暫用品，並非完整重製來源所有視覺。

## 已定位與修正的失敗

1. 連續載入 BM03 → BM04 時，Pixi 全域 alpha-mask pool 留下已釋放 shader 引用。低效能層改用核准合成底圖；高效能 WebGL 使用既有 mesh mask，略過該水面 mask／caustics 路徑。修復後逐圖切換通過；不修改供應商 Pixi 或一般 Battle。
2. 重設 viewport 後第一個量測曾讀到前一尺寸的 scrollWidth；原始失敗保留。加入溢出節點診斷後未重現，且四尺寸通過；場景容器另外裁切暫態 canvas 範圍。沒有把原始失敗標成 PASS。
3. 自我審查發現 ZONE 可在遮擋另一側落點，新增測試先證明失敗，再在扣 TP 前驗證視線；修正後通過。
4. 敵方沒有玩家 partnerId，動作適配原本落回預設序列；改從穩定 speciesId 查找該角色體型，並加入實際敵方施招動畫觀察。
5. 合併 main 後的全 CI 在 Windows 為 2,941 通過／2 失敗；兩個失敗都是歷史 `.txt` 原碼基準被 Git checkout 成 CRLF、現有 `.js` 是 LF，逐字比較因此失敗。已為這兩份原碼基準明訂 LF 並重新驗證；未改動測試斷言、基準語意或籠子／進化程式。

## 實際限制

新動作與最終效果美術待交付；193 隻尚未逐隻做視覺動作驗收。目前是本機對 AI 的可玩接力，沒有即時多人連線。平衡是第一版，實體手機手感與長時間不同機型效能待使用者實測。戰場朝向在進場時決定，中途旋轉手機只調整視窗與按鍵，下一場才重新旋轉地形。高效能海島的部分水面 caustics 暫不啟用；低效能層使用合成底圖。新增文案提供繁中／英文，其餘語系依原有機制回退英文。
